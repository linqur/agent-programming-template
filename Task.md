# Развитие шаблона

## Подход

- Развиваем шаблон постепенно, небольшими шагами.
- Каждый шаг: обсуждение → решение → фиксация в файлах.
- Задача шаблона — не изобрести новое, а свести существующие
  практики и принципы в единую согласованную систему, где они
  дополняют друг друга и не конфликтуют (по аналогии с тем, как
  чистая архитектура объединила ранее разрозненные подходы).
- Любое решение проверяем по цели из README:
  делает ли оно работу агента предсказуемее и прозрачнее
  и согласуется ли с уже принятыми решениями.

## Принятые решения

- Корень репозитория — проект самого шаблона
  (свои README.md и AGENTS.md).
- Шаблон проекта находится в `template/`.
  Пока шаблон один; при появлении второго пересмотрим структуру.
- `template/AGENTS.md` — точка входа для агента. Он не дублирует
  информацию, а ссылается на подробные документы.

## План

1. [ ] Корневой AGENTS.md: правила работы над шаблоном,
       `template/` — заготовка, а не инструкции.
2. [ ] README: механизмы, структура, использование, статус.
3. [ ] Скелеты файлов, на которые ссылается template/AGENTS.md:
       `.agents/architecture/`, `.agents/engineering/`,
       `openspec/config.yaml`, `Makefile`, `README.md`.
4. [ ] Раздел «Границы и завершение работы» в template/AGENTS.md:
       когда спрашивать человека, критерии готовности, формат отчёта.
5. [ ] Явный критерий, когда допустимо работать без OpenSpec.
6. [ ] Перенос правил из HTML-комментариев в основной текст.
7. [ ] Создание проекта из шаблона (`make new`)
       и заполнение плейсхолдеров агентом.
8. [ ] git init.

## Открытые вопросы

- Как устроен OpenSpec workflow и что настраивается в config.yaml.
- Копирование шаблона или copier (с обновлением созданных проектов).
- `openspec init` создаёт/дописывает управляемый блок в корневой
  AGENTS.md — как совместить с нашим template/AGENTS.md.

## Изучить (заимствовать идеи, не заменять)

- agentic-coding-rulebook — AGENTS.md с плейсхолдерами (п. 6, 7).
- agents-file-templates-and-skills — скилл заполнения AGENTS.md (п. 7).
- Agent Guardrails Template — границы и безопасность агента (п. 4).

## Референсы

Ближайшие по идее проекты. Можно брать за образец решений,
но они не закрывают нашу задачу: архитектура в них — это решения
по ходу (ADR, C4), а не действующие правила; инженерные принципы —
только критерии ревью, а не постоянный документ проекта.

- [intent-driven-template](https://github.com/intent-driven-dev/intent-driven-template)
  (OpenSpec + OpenCode). Взять:
  - правила в `openspec/config.yaml`, привязывающие скиллы к артефактам;
  - неизменяемые ADR (`adr/`), новое решение — новый ADR;
  - скилл grill-me — уточнение требований до спецификации;
  - скиллы в `.agents/skills/` — совместимо с нашей `.agents/`.
- [The Agentic Startup](https://github.com/rsmdt/the-startup)
  (плагин для Claude Code, свой процесс без OpenSpec). Взять:
  - `CONSTITUTION.md` — проверяемые правила с уровнями строгости
    (L1/L2 блокируют завершение);
  - структуру `docs/domain`, `docs/patterns`, `docs/interfaces`.
